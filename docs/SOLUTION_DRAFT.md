# Solution: LP-0018 — OpenStreetMap map snapshots on Logos: on-chain registry, Storage distribution, SDK and CLI

## Summary

An original, dual-licensed system that registers dated OpenStreetMap snapshots on the Logos
Execution Zone, stores the files in Logos Storage, and lets anyone discover, download and verify
them without trusting the host. It ships a SPEL registry program, a Rust SDK with a C ABI for
Basecamp modules, and a CLI covering every operation the prize lists. Every write is confirmed by
reading the chain back; every download is checked against the registered MD5; coverage is
verified exactly as the prize describes (Storage bytes against Geofabrik's published MD5).

## Approach

### Registry program (SPEL)

One account per region at a program-derived address (`["osm-region", region]`), because the
closed set has 72 regions and a single account would exceed LEZ's 100 KiB account limit at full
history. Each account keeps an append-only history of at most 8 entries; each entry has the
prize's fields plus `registered_by` and up to 16 `hosts`, both taken from the transaction signer.
A copied registration adds the copier as a host and never hides the original. The program checks
every field with the shared `osm_core` crate: region in the closed set with matching parent and
level, a dated Geofabrik source URL whose date equals `version`, MD5 format, size bounds, and a
millisecond timestamp bound to block time. There is no admin, fee or init step.

### Storage and verification

Files are uploaded with exponential back-off and jitter; downloads stream to disk and are kept
only if their MD5 equals the registered checksum, so junk entries are skipped. Hosted regions are
discovered and downloaded without Geofabrik (checked in CI with Geofabrik blocked).

### SDK, C ABI and CLI

`osm_sdk` reads the registry over JSON-RPC with a bounded decoder (fuzzed), resolves regions to
CID and metadata, downloads and verifies, checks for updates and coverage. `osm_ffi` exposes the
consumer API to Basecamp modules as JSON-in/JSON-out C functions, tested under ASan/UBSan. The
`osm` CLI covers host, bulk host, batch registration from a manifest, lookup by region, parent or
CID, update check, download and local import.

### LEZ 0.4

0.4 replaces LEZ's plan/apply model with actors. The registry already runs as an actor program
on a local v0.4.0-rc1 sequencer with the same data layout (signed host actor → clock-asserted
timestamp → region actor through a PDA seed). *Pending:* SPEL support for 0.4 and the public
deployment.

### What was tried and did not work

Recorded in `docs/tried-failed.md` and, for upstream defects, `docs/BUGS_FILED.md`. Examples: a
single registry account (too large), seconds instead of milliseconds (transactions included but
not applied), `Vec<AccountMeta>` before the signer in SPEL (same symptom), two defects in the
SPEL-generated client, the Storage `exists` response shape differing from its OpenAPI file.

## FURPS Self-Assessment

### Functionality
Discovery, host, bulk host, import, update check, download and the registry with query by
region, parent and CID run end to end on LEZ v0.3 (local sequencer and public testnet), with
negative tests on a real sequencer (18/18). *Pending:* testnet 0.4.

### Usability
CLI with JSON output and documented exit codes; SDK guide with a worked example; C ABI.
*Pending:* the Basecamp app.

### Reliability
Upload retries with back-off, typed errors with plain messages, confirmed writes, atomic local
writes surviving `kill -9` (200 rounds), owner-only data files, bounded decoders (fuzzed),
streaming of multi-GB files (2 GiB at 2.7 MB peak memory).

### Performance
Executor cycle counts for `register` (49,970 user cycles) and `register_batch` with 1/5/10/16
regions in `docs/cycles.md`; fees measured on a real sequencer.

### Supportability
CI on Linux, macOS and Windows; end-to-end job with a real sequencer and Storage nodes; Storage
retrieval by an independent node; IDL regeneration diff; README cold start; doc-truth check;
daily liveness, LEZ-release and fuzz jobs; `demo.sh`. *Pending:* nix module builds and the
catalog.
