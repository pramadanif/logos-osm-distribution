# Walkthrough

A tour of the system for anyone who has to explain it, including in an authorship interview.
Each section says what a part does, why it is built that way, and where to look.

## The idea in one paragraph

Geofabrik publishes OpenStreetMap extracts as `.osm.pbf` files with an MD5 next to each dated
snapshot. We put those files into Logos Storage, where a file is addressed by its content (CID),
and record on the LEZ chain which CID holds which region's snapshot, with Geofabrik's MD5 and the
URL of the dated file. Anyone can then find a region on-chain, fetch it by CID from any Storage
node, and check the MD5 without trusting the node or us.

## Parts

| Part | Path | What it does |
|------|------|--------------|
| Region set + validation | `osm_core` | the 72 prize regions (Rust table equal to `regions/predefined.json`) and every input rule (dated URL, MD5 format, size and time bounds). `no_std`, so the on-chain program and the SDK share one copy |
| Registry program (LEZ v0.3) | `programs/osm_registry` | SPEL program: `register`, `register_batch`, `unhost`; one account per region; IDL generated by SPEL into `idl/` |
| Registry program (LEZ 0.4, step 1) | `programs/osm_registry_v04` | the same rules as an 0.4 actor program (no SPEL yet) |
| SDK | `osm_sdk` | discovery, Geofabrik client, MD5, Storage REST client with retries, registry reader, download with verification, coverage check, local data folder |
| C ABI | `osm_ffi` | JSON-in/JSON-out C functions over the consumer part of the SDK, for Basecamp modules |
| CLI | `osm_cli` (`osm`) | every user action from the terminal |
| Basecamp modules | `basecamp/osm-distribution`, `basecamp/osm-sdk`, `basecamp/osm-app` | core module with the full API (writes signed by `lez_core`), read-only SDK module for other modules, and the app; index in `module.json` |
| Templates | `examples/consumer-module`, `examples/distribution-consumer-app` | starting points for other people's modules |
| Write path (CLI) | `programs/osm_registry/lez_adapter_v03` (`osm-chain`) | builds and signs transactions with the SPEL-generated client, then waits until the change is visible on-chain |

## Decisions worth being able to defend

1. **One account per region, not one registry account.** LEZ v0.3 caps an account at 100 KiB;
   72 regions x 8 entries x 16 hosts would need about 420 KiB. Per-region accounts are about
   6 KB each at maximum fill (test `account_at_maximum_fill…`). ADR 0001.
2. **Append-only history with a host list.** A registration never overwrites; the same CID from
   another signer adds a host; a new CID adds an entry; at most 8 entries per region. Griefing
   with fake CIDs cannot hide a good entry because downloads verify the MD5 and skip bad ones.
   ADR 0002, `osm_sdk/src/fetch.rs`.
3. **No admin, no init.** On LEZ v0.3 writing a program's own shard is enough; there is nothing a
   first caller could capture, and a copied transaction only adds the copier as a host
   (probe p01). ADR 0003.
4. **The signer is the registrant.** `registered_by` and hosts are taken from the transaction
   signer by the program; no argument can set them (IDL check in docs/claims.md).
5. **Timestamps are milliseconds and bound to block time.** We first used seconds; the
   transaction was accepted by the sequencer but changed nothing because it fell outside its own
   validity window. That is also why every write is confirmed by reading the account back.
   docs/status/phase-B.md.
6. **Dated snapshots.** We register `<region>-YYMM01.osm.pbf`, not `-latest`, because the prize
   checks the MD5 "for that snapshot" and Geofabrik keeps first-of-month files for months.
   docs/status/geofabrik.md.
7. **Geofabrik is optional.** Hosted regions are discovered and downloaded without it; CI blocks
   download.geofabrik.de and checks this (P-R4).
8. **Two network targets behind one seam.** LEZ v0.3 now (public testnet, faucet) and 0.4 for the
   prize. 0.4 changes the programming model to actors; the data layout stays the same, so the SDK
   reads both. docs/status/lez-04-port.md.

## How a host operation flows

`osm host --region kenya` → `Geofabrik::latest_snapshot` (reads the `-latest` redirect) → first
of month → `download_snapshot` (resumable, free-disk check, MD5 vs Geofabrik's `.md5`) →
`upload_with_retry` to the Storage node (exponential back-off with jitter) → `osm-chain register`
→ the SPEL client signs `register` → the adapter polls the region account until the entry with
our CID and our account appears, or fails with S103.

## How the evaluator's check works

`scripts/verify-onchain.sh`: compare the program's on-chain ImageID with `networks.json`, read all
72 region accounts, fetch each hosted CID from Logos Storage, hash it, compare with Geofabrik's
published MD5 for the snapshot, count regions and countries (a decomposed country counts through
any verified subregion), exit 0 only at 25/15. Code: `osm_sdk/src/coverage.rs`.
